# Decisions

Each item gives the decision, the evidence, and what would reopen it. Items 1 to 7 were settled with the product specification on 2026-10-14; the rest were settled during the pre-implementation pass on the same day. Spike runs were made on Windows 11 Pro 10.0.26200 with Claude Code 2.1.296, Node 26.4.0, gh 2.91.0 and git 2.56.0; the raw artifacts live outside the repository.

1. **A self-contained repository.** Every file is written for this suite. No file imports history, links to another project, maps names, records an acceptance run made elsewhere, or notes what came before. Lessons enter the requirements as rules with no source line. Reopens: never; this is the premise of the repository.
2. **Plugin names `rules`, `loop`, `audit`, `repo-docs`.** They give `/rules`, `/loop:run`, `/audit:run` and `/repo-docs`. Spike 8 confirmed that a skill named like its plugin answers to the bare `/rules` as well as `/rules:rules` on 2.1.296; the documentation describes only the namespaced form, so the README shows both. Reopens: a host release where the bare form stops working, which the acceptance item for `/rules` would catch.
3. **`repo-docs` is written from its requirements alone.** Requirements 197 to 212 specify the model, the pointer grammar and the hook in full; nothing is copied from another plugin. Reopens: never.
4. **Both house-rule edits ship.** The two Working items in requirements 19 and 20. Removing any stop was rejected. Reopens: the owner's say-so.
5. **No effort tiers.** One default run budget of 240 minutes, the risk floor, and a prose effort hint. A tier would choose a model per step, and the suite has one model per role, so a tier could only set the budget, which the hint and `.reimagine.json` already do. Reopens: field runs that need a budget the hint and the configuration cannot express.
6. **State directory `.reimagine/`, namespaced per plugin.** The loop writes `.reimagine/loop/<branch-slug>/` and adds `.reimagine/` to `.git/info/exclude`; the audit writes `.reimagine/audit/<run-id>/` only when `.reimagine/` is already ignored, and otherwise falls back to the plugin data directory, because the audit never writes under `.git/`. The specification named `.reimagine/<branch-slug>/`; the extra level keeps a branch slug from colliding with an audit run id. Repository configuration is `.reimagine.json`. Reopens: a host feature that gives plugins a per-repository ignored directory.
7. **Azure DevOps pull request publishing is out of scope.** Reads and discussion comments go through an MCP tool or `az`; a run on an Azure DevOps remote ends `prepared` with the push command. Reopens: a tested `az repos pr create` path with an acceptance item.
8. **No attribution hook.** Spike 5: with the attribution setting off, three of three commit runs on 2.1.296 (opus, sonnet, opus) produced no trailer; with it on, the model added one and said the session setup told it to. A hook denying a commit that carries a trailer while the setting is off would guard against a behavior that did not occur. Requirement 11 keeps the rule that the loop never types a trailer. Reopens: a trailer appearing in the field with attribution off.
9. **No `userConfig` anywhere.** Spike 4: a boolean option with `default: true`, referenced as `${user_config.flag}` in a hook command, failed every run while unset with `Plugin option "flag" isn't set. Open /plugin manage to configure it`. The default was not substituted. Options are expressed in `.reimagine.json` or in prose instead. Reopens: a host release that substitutes defaults, confirmed by rerunning the spike.
10. **Forbidden names are enforced from outside the repository.** A list of forbidden names inside the repository would itself be a file holding them. Lint reads `LINT_DENY_TOKENS` from the environment when set and fails on any tracked file containing a listed token; CI leaves it unset and the implementing session sets it locally before every commit. Reopens: never; the need ends with 0.1.0.
11. **Fixture literals are observed, not computed.** The audit script suites compare bytes and shas that embed strings (`reimagine-handoff: 1`, `# audit report: `, `audit:auditor`, the `working-tree.sh` commit identity, the fixture handoff blob). Every literal that depends on such a string is produced by running the fixture builder once and pasting the observed value, in its own commit, so the diff shows which values follow from which strings. Reopens: never.
12. **`jq` is an optional prerequisite of the audit.** Three scripts need it; Git for Windows does not bundle it; a Node rewrite would add code without a suite behind it. The README names it and stage 1 warns when it is missing. The repo-docs hook stays free of it. Reopens: `jq` installs proving a recurring support cost, which would justify the rewrite with its own suite.
13. **The credential scan belongs to the loop.** The specification places the scan on ticket text before it is written to a run directory. The loop writes ticket text into its record, so it scans. The audit redirects forge reads to files without passing them through the model and keeps its run directory ignored; adding a scan there would be new scope. Reopens: a field run where audit run-directory contents leak into something published.
14. **Trigger phrases live in the skill description.** Spike 1: a description naming "reimagine loop" and "run the loop" invoked the skill in two of two opus runs; a terse description without the phrase also invoked a skill named `loop` once; a negative control did not. `when_to_use` is not used because the spike did not cover it and the host appends it to the description anyway. Reopens: a trigger miss in acceptance.
15. **Reviewer fallback is written into the skill.** Spike 2: `fable` and `opus` are accepted agent model names on this account; an unknown name fails the Agent call with an API 404 that the orchestrator sees. The skill retries once at `opus` on a model or tool error, records the swap, and stays swapped. Reopens: a host feature that falls back by itself.
16. **`steps.json` is the loop's completion record.** Parsing prose for resume is fragile; a JSON entry written `complete` only after its outputs exist is a reliable single source, and the audit's `stages.json` follows the same pattern. `run.md` stays the narrative. Reopens: never.
17. **The diff review has a defined request.** Requirement 66 states what a diff reviewer receives: plan, inputs, acceptance criteria, dispositions, and the diff read from the merge-base after `git add -N`. No credential scan runs on the diff: it stays with the session's own model provider. Reopens: a finding that a reviewer subagent surfaced a credential into the record.
18. **Review calls get a 30-minute budget.** A live run's final review over 37 files took 20 minutes 42 seconds and blocked at a 20-minute budget with no path to resume. Review passes have their own `review` budget of 30 minutes, and the idempotent record lets a blocked step 5 be rerun. Reopens: budget data from the first ten field runs.
19. **A missing `code-review` skill does not block a higher-risk run.** An Opus subagent reviewing a patch file serves worktree and additional-repository diffs; the same path serves when the skill is not listed. Reopens: never.
20. **The loop edits only pull request bodies it wrote.** A body belongs to whoever wrote it. A pull request this loop opened is recorded in `steps.json` and its body is updated once per run; a pull request the loop did not open gets a comment only. Reopens: never.
21. **Second opinion: sentinels, 60-id batches, one launch per batch.** Sentinels prove the agent read each input and feed the low-tier gate credit. Batches of 60 keep one answer within a size the orchestrator can check position by position; the number is revisited when a run shows a reason. There is no follow-up call and no inline input form: an unacknowledged input fails the stage, and the ladder relaunches. Reopens: a run where batching changes the verdict.
22. **Four audit commands.** `run`, `resume`, `act` and `handoff` are thin forwarders; `resume`, `act` and `handoff` take their few flags because they take ids and files, not prose. The prose form "reimagine audit ..." is the primary entry. Reopens: never.
23. **`commit: true` snapshots go to `docs/runs/<branch-slug>/`.** Each publishing run commits the plan and `report-<n>.md` with state `publishing`; the terminal report is posted as a pull request comment. Reopens: a repository convention that names another place, which `repo-docs` placement would then follow.
24. **Mechanisms not built, and why.** A one-request-per-session implementer transport: slices run in parallel when their files are disjoint. A model-provider availability probe before a run: the host is the only provider. Request files and thread ids for reviewers: each review is a fresh Agent call with the request in its prompt. A no-retry rule for a process that may outlive its call: subagents end with their call. A 3,600-second cap on implementer timeouts: budgets are minutes in `.reimagine.json`. A headless cap on the second opinion: it is an Agent call under the orchestrator's budget. Running the second opinion from the repository root: the agent reads absolute paths. A version gate between plugins: no plugin depends on another. An on-off option for a provider: there is one provider. Sending an empty diff to review: the step records "no changes" instead. Each is recorded so nobody adds it without a new reason. Reopens: never.
25. **The staleness notice display is an acceptance item.** Spike 3 showed the hook running with outcome success and the `systemMessage` JSON on stdout, but a headless run cannot show what the user sees. Reopens: never; it is checked interactively.
26. **The idempotency spike ran on git primitives only.** Spike 7 verified merge-base, explicit-refspec fetch, fast-forward over a foreign commit, an append-only record under `.reimagine/` excluded from status, the remote-head check, the three-dot diff, and the existence of `gh pr edit --body-file` and `gh pr comment --body-file`. A second invocation of the skill on a branch with an open pull request cannot run before the skill exists, and opening a pull request needs its own ask. That run is the acceptance item of the idempotency milestone. Reopens: never.
27. **CI pins a Claude Code version at least seven days old.** The validate job installs a fixed version with the autoupdater disabled so a new release cannot change the result without a commit here. 2.1.296 is the version the spikes ran on and is recorded in acceptance.md; the pin is chosen when the CI milestone lands. Reopens: a validation change in a newer host release.
28. **Hub cap 60 lines, spoke cap 200.** The specification named about 60 for the hub; 200 follows the host's guidance that each instruction file stay under 200 lines. Reopens: a host change in context handling.
29. **One script for the rules plugin.** The staleness notice is the `session-start` verb of `rules.mjs` rather than a module of its own; the script budget is 700 lines. Reopens: never.
30. **No separate plan command.** "plan only" is a mode read from prose, so `/loop:run` is the only command. Reopens: never.
31. **Deferred audit helpers.** A stage 4 and 5 bookkeeping helper, `ledger.sh build6`, `report-parts`, `count`, and an Azure DevOps exporter are not built; each needs fixtures and a design review of its own. Reopens: a field run where hand bookkeeping slipped, recorded as an issue.
32. **The marketplace `metadata.version` is the catalog's own.** With no suite version, it is raised whenever an entry changes, and lint only requires it to be present and well formed. Reopens: never.
33. **Implementers are told to stay in scope.** A live run saw an implementer widen a `gh` command unasked and a brief cause a defect; requirement 104 makes the brief say so, and the slice review catches it. Reopens: never.
34. **Baseline failures match by test name.** Two of sixteen baseline failures in a live run passed later, so counts are not a stable match. Reopens: never.
